# hsw-editor HTTP API

Base URL `http://127.0.0.1:8794` (port in `~/.config/hsw-editor/config.json`). JSON in, JSON out, UTF-8.
The wall/op types are defined once, in `packages/core` (`schema.ts`, zod); every request body below is
validated against them. Import `applyOp`, `OpSchema`, `parseWall`, `opJsonSchema()` instead of re-modelling.

## Security

- The daemon binds loopback only. A request is refused with `403 forbidden_host` unless its `Host` header is
  `127.0.0.1`, `localhost` or `[::1]` (DNS-rebinding guard), and with `403 forbidden_origin` if an `Origin` header is
  present that is not the same origin or one of `HSW_EDITOR_ALLOWED_ORIGINS` (default: the Vite dev server,
  `http://127.0.0.1:5194`, `http://localhost:5194`). Requests without `Origin` (CLI, agents, curl) pass.
- No CORS headers are ever sent (no `Access-Control-Allow-*`); cross-origin browser reads are impossible.

## Conventions

- Ids match `[A-Za-z0-9][A-Za-z0-9_.-]{0,63}`; omitted item/photo/model ids are generated by the server.
- **Wall coordinates**: millimetres; x right, y up, z out of the wall; board lower-left corner = origin. Cell centres:
  `x = (col + .5) * colPitch`, `y = (row + .5 + (col odd ? .5 : 0)) * rowPitch` (HSW: 20.4382 x 23.6 mm). Rotations in
  degrees, `rotZ` about the wall normal (holders are expected at multiples of 60; other angles are allowed and raise a `rotation_off_symmetry` warning). See `packages/core/src/grid.ts`.
- `rev` is a monotonic integer per wall: +1 for every op that changes the wall (undo and redo included). An op that
  changes nothing does **not** bump it.
- Actor: `{ "kind": "human" | "agent" | "cli", "name"?: string }`, recorded with every history entry and SSE event.
  Taken from the `actor` body field; defaults to `{kind:"human"}` (UI) and `{kind:"cli"}` (`hsw-editor wall ...`).
- Errors: `{ "error": { "code": string, "message": string, "details"?: ... } }` with the status below.

| Status | `error.code`                                       | Meaning                                                                    |
| ------ | -------------------------------------------------- | -------------------------------------------------------------------------- |
| 400    | `invalid_json`, `invalid_body`, `invalid_id`       | Malformed JSON / body does not match the schema (`details`: list of issues) |
| 403    | `forbidden_host`, `forbidden_origin`               | Guard rejected the request                                                 |
| 404    | `not_found`, `wall_not_found`, `asset_not_found`, `request_not_found`, `unknown_job_kind`, `job_not_found` | Unknown route / wall / file / request / job |
| 409    | `rev_conflict`                                     | `baseRev` is stale; body also has `wall` (current) and `currentRev`        |
| 409    | `wall_exists`                                      | `POST /api/walls` with an id that is taken                                 |
| 409    | `nothing_to_undo`, `nothing_to_redo`               | Empty undo/redo stack                                                      |
| 409    | `undo_conflict`, `redo_conflict`                   | The stored inverse/op no longer applies to the current wall                |
| 409    | `request_closed`                                   | The input request was already answered or cancelled                        |
| 413    | `payload_too_large`                                | Upload above the limit (photos 40 MB, models 100 MB)                       |
| 415    | `unsupported_media_type`                           | Not a JPEG/PNG/WebP photo, not a binary glTF (`.glb`) model                |
| 422    | `heic_conversion_failed`                           | A HEIC photo could not be converted to JPEG (needs `uv` and, once, network) |
| 501    | `heic_converter_unavailable`                       | HEIC upload but `uv` is not installed                                       |
| 422    | `op_failed`                                        | Op refused by the reducer: `details` = `{ opIndex?, code }` (see below)    |
| 422    | `invalid_request`                                  | An input request points at an item/photo/model that is not on the wall     |
| 500    | `internal`                                         | Bug; the wall on disk is still consistent                                  |

Reducer codes (`details.code`): `item_not_found`, `item_exists`, `item_locked`, `photo_not_found`, `photo_exists`,
`model_not_found`, `model_exists`, `invalid_op`. A request with several ops is atomic: one refused op = nothing applied.

## Health

`GET /api/health` -> `{ ok: true, name: "hsw-editor", version, home }`.

## Walls

| Method & path             | Body / query                                                      | Response                                    |
| ------------------------- | ----------------------------------------------------------------- | ------------------------------------------- |
| `GET /api/walls`          |                                                                   | `{ walls: WallSummary[] }`                  |
| `POST /api/walls`         | `{ name, id?, board? (partial; defaults 48x32 HSW), actor? }`     | `201 { wall, warnings, canUndo, canRedo }`  |
| `GET /api/walls/:id`      |                                                                   | `{ wall, canUndo, canRedo, warnings }`      |
| `DELETE /api/walls/:id`   |                                                                   | `{ ok: true, trashedTo }` (moved to `walls/.trash/`, never unlinked) |
| `GET /api/walls/:id/history` | `?since=<rev>&limit=<n>`                                       | `{ entries: HistoryEntry[] }` (rev > since) |
| `GET /api/walls/:id/export`  |                                                                | `{ format: "hsw-editor-wall", version: 1, wall, history }` |

`WallSummary = { id, name, rev, items, photos, models, updatedAt }`.
`HistoryEntry = { rev, ts, actor, kind: "create" | "op" | "undo" | "redo", op, inverse, ref?, label? }` — `op` is
what was applied to the wall at `rev`; for `undo`/`redo`, `ref` is the rev being undone/redone.

## Ops

`POST /api/walls/:id/ops`

```json
{ "ops": [ { "type": "moveItem", "id": "i-1", "to": { "cell": { "col": 4, "row": 2 } } } ],
  "baseRev": 17, "actor": { "kind": "agent", "name": "omp" }, "label": "optional batch label" }
```

- `baseRev` (optional): if present and not equal to the wall's current `rev` the request fails with `409 rev_conflict`
  and nothing is applied. Omit it to apply on top of whatever is current (last writer wins).
- More than one op is wrapped into a single `batch` op: one rev, one history entry, one undo step.
- Response `200 { rev, changed, op, inverse, wall, warnings }`. `changed:false` = every op was a no-op (nothing
  written, `rev` unchanged). `warnings` are geometry/reference problems (`cell_collision`, `out_of_board`,
  `cell_out_of_board`, `rotation_off_symmetry`, `missing_parent`, `missing_photo`, `missing_model`); they never block.

Op types (`packages/core/src/schema.ts`; JSON schema via `opJsonSchema()`): `addItem`, `removeItem`, `moveItem`,
`rotateItem`, `setParams`, `setVariant`, `lock`, `addPhoto`, `removePhoto`, `setCalibration`, `setBoard`, `rename`,
`addModelRef`, `updateModelRef`, `removeModelRef`, `batch`. Locked items refuse every op except `lock`.

`POST /api/walls/:id/undo` and `/redo` — body `{ baseRev?, actor? }` -> same response as ops. Undo/redo is a single
linear stack across all actors: it applies the stored inverse of the newest not-yet-undone op.

## Assets

- `POST /api/walls/:id/photos` — `multipart/form-data`: `file` (JPEG/PNG/WebP/AVIF/HEIC; EXIF orientation is applied and HEIC/AVIF converted, so stored pixels are upright), optional `name`, `actor` (JSON string).
  Stores `photos/<id>.<ext>`, applies an `addPhoto` op. `201 { photo, rev, wall }`.
- `GET /api/walls/:id/photos/:photoId/file` — the image (`cache-control: private, max-age=31536000, immutable`).
- `POST /api/walls/:id/models` — `multipart/form-data`: `file` (binary glTF, `.glb`), optional `label`, `forItemId`, `actor`.
  Stores `models/<id>.glb`, applies `addModelRef` (status `candidate`). `201 { model, rev, wall }`.
- `GET /api/walls/:id/models/:modelId/file` — the model file.
- Model references without a file (found online, bank candidates) are plain `addModelRef` / `updateModelRef` ops.

## Live events (SSE)

`GET /api/walls/:id/events` (`text/event-stream`). Each frame has `id: <rev>`.

| `event`     | `data`                                   | When                                                                  |
| ----------- | ---------------------------------------- | --------------------------------------------------------------------- |
| `snapshot`  | `{ wall }`                               | On connect without `Last-Event-ID`/`?since`, or when resume is impossible |
| `op`        | a `HistoryEntry` (`rev`, `actor`, `op`…) | Every applied op, undo and redo, in rev order                         |
| `heartbeat` | `{ rev }`                                | Every 15 s; also lets a client detect that it missed revs             |
| `deleted`   | `{}`                                     | The wall was deleted; the stream then closes                          |
| `request_input` | `{ request }`                        | An input request was opened; open ones are re-sent after every (re)connect (no `id`) |
| `request_resolved` | `{ id, status, answer? }`         | A request was answered or cancelled (no `id`)                         |

Resume: reconnect with `Last-Event-ID: <rev>` (EventSource does this automatically) or `?since=<rev>`; the server
replays every entry with a greater rev, then continues live. If `since` is ahead of the server's rev a `snapshot` is
sent instead. Clients apply `op` events with the same `applyOp` reducer from `packages/core` and resync (refetch the
wall) if they see a gap in `rev`.

## Input requests

An agent or job asks the human a question while it works; the UI renders a widget, the human answers, the asker gets the
answer. Requests never change the wall and are not in the undo history (the UI applies the wall edits itself via `/ops`
first, then answers). Persisted in `walls/<id>/requests.json`. Types: `packages/core/src/request.ts`.

`InputRequest = { id, kind, status: "open" | "answered" | "cancelled", itemId?, photoId?, title?, prompt?, payload, createdBy, createdAt, resolvedBy?, resolvedAt?, answer? }`

| `kind`        | `payload`                                                                                                  |
| ------------- | ---------------------------------------------------------------------------------------------------------- |
| `dimension`   | `{ fields: [{ key, label?, unit: "mm", min?, max?, fitted?, suggested? }] }`                               |
| `variant`     | `{ candidates: [{ id, bankId?, label, score? }] }`                                                         |
| `compare`     | `{ modelRefIds: [Id, ...] }` (>= 2 entries of `wall.models`)                                               |
| `calibration` | `{ photoId, mode: "two-point" \| "grid" }`                                                                 |

| Method & path                              | Body / query                    | Response                                         |
| ------------------------------------------ | ------------------------------- | ------------------------------------------------ |
| `POST /api/walls/:id/requests`             | `{ request: { kind, payload, itemId?, photoId?, title?, prompt? }, actor? }` (default actor `{kind:"agent"}`) | `201 { request }`; `422 invalid_request` if an id does not exist on the wall |
| `GET /api/walls/:id/requests`              | `?status=open\|answered\|cancelled` | `{ requests }`                               |
| `GET /api/walls/:id/requests/:rid`         | `?wait=<ms>` (max 120000)       | `{ request }`; with `wait`, blocks while the request is open (long poll) |
| `POST /api/walls/:id/requests/:rid/answer` | `{ answer: <any JSON>, actor? }` | `{ request }`; `409 request_closed` if already resolved |
| `POST /api/walls/:id/requests/:rid/cancel` | `{ actor? }`                    | `{ request }`                                    |

In-process jobs use `ctx.walls.askUser(wallId, request, actor, signal)` (`apps/server/src/jobs.ts`), which opens the request
and resolves with it once answered; aborting the signal cancels it.

## Bank and other modules

The bank routes (`/api/bank/*`, `/bank/assets/*`) are owned by `packages/bank` (see `docs/bank.md`). Features owned by other
packages (omp bridge, draw backends, vision proxy, bank) plug into the daemon through `apps/server/src/modules.ts`
(`ServerModule`); they run after the loopback guard, so they inherit it.

## Jobs

Long-running work (vision, drawing). Handlers are registered in-process with `registerJob` (`apps/server/src/jobs.ts`).

| Method & path                 | Body / query                  | Response                                              |
| ----------------------------- | ----------------------------- | ----------------------------------------------------- |
| `GET /api/jobs`               | `?kind=&wallId=&state=`       | `{ jobs: Job[] }`                                     |
| `POST /api/jobs`              | `{ kind, input, wallId? }`    | `202 { job }` (`400 invalid_body` if `input` fails the handler's schema, `404 unknown_job_kind`) |
| `GET /api/jobs/:id`           |                               | `{ job }`                                             |
| `POST /api/jobs/:id/cancel`   |                               | `{ job }` (aborts the handler's `signal`)             |
| `GET /api/jobs/:id/events`    | `Last-Event-ID`               | SSE: `state`, `progress`, `log`; closes after the terminal state |

`Job = { id, kind, wallId?, state: "queued" | "running" | "succeeded" | "failed" | "cancelled", progress?: { done?, total?, fraction?, message? }, result?, error?, createdAt, startedAt?, finishedAt? }`.

## Static app

Everything else is the built web app (`apps/web/dist`): hashed `/assets/*` are `immutable`, `index.html`, `sw.js`
and manifest are `no-cache` (ETag, `304`), unknown paths fall back to `index.html` (SPA).

## On-disk layout

`$HSW_EDITOR_HOME` (default `~/.local/share/hsw-editor`):

```
walls/<id>/wall.json        snapshot (atomic write: tmp + fsync + rename)
walls/<id>/history.jsonl    one JSON entry per rev, appended + fsynced BEFORE wall.json is replaced
walls/<id>/photos/ models/  uploaded and generated assets (photos/derived/ for drawn views)
walls/.trash/               deleted walls
server.lock                 pid of the single writer
```

The daemon is the single writer; the CLI and agents go through HTTP. After a crash the wall is rebuilt from
`wall.json` + the tail of `history.jsonl`.
